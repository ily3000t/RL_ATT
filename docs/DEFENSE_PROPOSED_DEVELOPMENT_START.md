# 自己防御方法的开发起点与并行比较

2026-10-07。根据用户最新意见，**现在开始自己的方法设计与原型开发，不将所有基础防御实现、调优或完整攻击矩阵的完成作为开始条件**。D3 比较方法与 D4 新机制可并行推进；这取代此前过于串行的“先完成全部基线测试，再开始新方法”建议。

## 已有问题足以启动研究，但尚不是贡献结论

已有证据支持两个不同的研究动机：

1. 原 OARL Robust 在开发交通上的搜索攻击防御收益不一致。控制性诊断还观察到集中交通的首次行为偏离即可导致终止，以及其他交通中持续攻击带来的额外损害；不是所有行为偏离都有害。
2. PGD 一致性基础对照在当前固定配置下，两个 run 出现低收益常动作策略；少碰撞、低 KL 同时存在，说明只看一致性和碰撞不足以判断任务是否得到保护。该方法尚未完成冻结策略攻击评估，退化的因果来源也未确认。

对应证据见 [OARL 防御对照](DEFENSE_BASELINE_RESULTS.md)、[控制性诊断](DEFENSE_CONTROLLED_REPLAY_RESULTS.md) 和 [PGD 长程结果](DEFENSE_PGD_LONG_RUN_RESULTS.md)。五模型的结果全部保留，不只研究 seed 2，也不只选择有利或危险的一个交通。

第一版的研究问题为：**在观测攻击下，如何保护动作选择的任务后果，同时保持有收益的状态相关决策，避免通过低收益常动作策略获得表面一致性？**

这是候选问题，不是已经证明的创新。“提高回报”“降低保守性”“使用累计后果”本身不足以定位贡献；具体机制与 ACoE、ATLA 及其他近邻工作的差异仍须核对。当前配置的一次负面结果不等于整个 PGD/SA 防御家族无效，也不能据此保证自己的方法有效。

## 两条工作线

| 工作线 | 当前任务 | 与另一条线的依赖 |
| --- | --- | --- |
| 自己的方法，优先 | 明确一个主要机制、数学目标、数据来源和梯度路径，独立实现最小原型，先做工程检查与短程训练 | 不等全部基础防御实现或调好；所选机制实际依赖的数据/训练支撑必须正确 |
| 比较与评估，持续推进 | 保留 Clean/OARL/PGD 当前冻结版本，建立新交通协议，补充必要的论文母方法和基础对照，对实际策略重新生成攻击 | 新交通登记要早于效果验证；完整强比较要早于正式论文结论，无需全部早于原型代码 |

不把自己的方法默认写成“PGD 一致性加覆盖再加恢复”。PGD 一致性仍是独立基础基线；ACoE 为优先候选出发点、ATLA 为备选，复用 OARL 工程不自动决定损失。对所选路线，必须解决它实际涉及的即时量、belief/off-policy 目标或动作后果来源；与该路线无关的未完成基础方法不应阻塞原型。

## 第一版的可审查开发内容

第一项方法分支先形成一份明确的规格，而不是再次启动所有基线调参：

- 只选一个主要增量，写清其要纠正的失败现象，以及现有母方法/对照为什么可能没有解决它。
- 写出训练目标和每项输入/标签的来源，标明 actor、critic、辅助模型的梯度路径；不能将动作无关常量误差当成有效策略梯度。
- 若使用 SUMO 控制分支，标签只来自同一真实 state 下实际执行的动作后果，所有回放、warmup、额外转移和网络调用计费；不把数值观测候选当作完整物理 state。
- 部署仍优先采用确定性 `16→128→3` actor，仅接收传入观测；训练特权不进入部署，不添加换道规则来绕过攻击，也不修改冻结攻击或 checkpoint。
- 预先写出机制关闭后的匹配控制组，检查更新、随机流、完整状态恢复和成本。这里的消融对象是自己的新增机制，而不是要求把所有基础防御逐层拆成自己的方法。
- 先通过短程工程检查，再启动明确记录的开发训练；初始版本失败同样保留。新方法效果不足不阻止合并已经验证正确的实现，但不能标成科学成功。

若母方法核心量仍无法被可信地提供，可比较替代数据来源或调整候选路线；不能为继续开发而伪造奖励、称未经校准的 critic 输出为真实后果，或将任意改动称为 ACoE 原算法复现。原型开发不要求整套比较全部完成，仍要求原型自身数学与实现定义完整。

## 基线公平性与结论要求

不追求先将每个基线调到好成绩。基线需要的是实现正确、配置有合理依据、数据权限和成本可比，以及对最终实际策略重新攻击。冻结的 PGD λ=0.1 版本继续保留；如果后来检查其他合理配置，应另设版本、登记开发集与搜索预算，不静默覆盖或据保留测试调参。

首轮开发的最小对照可以使用已有 Clean、OARL Robust、PGD 一致性和所选机制对应的关闭版本；若自己的机制源于论文适配，正式贡献结论还必须与同等适配的母方法比较。PGD 对抗交互训练、随机平滑/EOT 等可以按研究问题和资源安排补充，不要求所有列出的防御都先成为最优模型。

验证至少分别回答干净收益、攻击后绝对收益、各自 Return Drop、碰撞及实际成本；低熵和少换道只是诊断，不单独奖励高熵或强迫换道。针对同一冻结策略重新生成 PGD、预算版 Zero-One 和 Single，不能以转移攻击代替适应性测试。

防御新交通 namespace 应与方法原型同时推进，并在第一次效果选择之前登记。工程检查可继续使用已有工程训练协议，不将其作为新交通验证；最终 split 30 不参与调参。正式保留测试在方法、配置和比较协议冻结后执行。

现在的推进顺序为：**问题与主要机制定义 → 第一版工程实现 → 小规模匹配开发比较 → 修正假设或验证增量 → 补齐强比较与自己的模块消融 → 独立最终测试**。不需要在第一步前把所有基线“调好”，也不以击败当前一个较弱配置替代整个贡献论证。
