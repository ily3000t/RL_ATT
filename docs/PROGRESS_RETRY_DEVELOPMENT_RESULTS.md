梯度分别减少 18.366% / 18.416%，forward 减少 15.064% / 15.115%。每个目标增加 600 个规划仿真步：87 个新转移、267 个 replay 步及 246 个预热步，合计增加约 0.45% / 0.46%。episode 初始 oracle setup 独立记录，以上是规划成本；审计已将其与完整 oracle 总账核对。不能将并行 wall time 直接解释为算法加速比。

Return / Safety 新版分别有 9,546 / 9,544 条去重停止决定，逐条与 margin、尝试序号、未找到的目标和停止原因核对。它们不等于被节省的 PGD 次数：后续探索与预算退出发生变化，实际重试分别少 9,038 / 9,036 次，总 PGD 尝试均少 8,933 次。

新旧版本的重试新分支记录逐条相同（不只是数量相同）。两个进入选中计划的分支仍是 checkpoint 1 的 episode 1/block 0 与 checkpoint 3 的 episode 5/block 180，均来自第一次重试。此样本支持保留第一次重试，但“进入选中计划”不能证明其对碰撞具有因果贡献；未执行的后续重启也不能标为不可达。

## 与既有基线的关系及下一步

同一开发交通、模型和预算下，历史预算版 Zero-One Return 的梯度为 50,124、forward 为 138,992、规划 shadow step 为 126,418；Safety 为 49,912、138,371、124,570，碰撞也均为 14/50。新版虽减少了相对 v0 的模型计算，三类总成本仍高于这些基线。因此本轮支持一个有限结论：进展规则改善了 v0 的计算分配，但没有支持更强安全攻击或整体资源优势的主张。原基线结果和 v0 负结果继续保留。

下一步保持停止规则、预算和 checkpoint 冻结，在同一开发集上用独立 attack seeds 1/2 复核成本和效果权衡；不能把两种目标或五个共享交通模型当成独立样本。若出现退化，应完整报告，不只挑选保留轨迹的 seed。之后再决定候选方法是否值得进入验证集。验证集和最终测试集本轮未使用，也未提前开发新模块或扩展场景。
